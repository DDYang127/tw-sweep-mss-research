# 第 1 部分：5 月研究與 10 月稽核

## 版本 1 的整體策略

5 月研究的起點（v1），之後所有版本都在這個基礎上加條件或改出場。

| 項目 | 內容 |
|---|---|
| 市場與方向 | 台股電子股，只做多 |
| 股票池 | 舊 `stocks` 表的 687 檔電子股 |
| 資料期間 | 2022-01～2026-05（當時誤以為資料只能回溯到 2022 年） |
| K 線 | 日 K，未還原股價 |
| 三種範圍 | 短（LTF，高低點左右各 2 根）、中（MTF，5 根）、長（HTF，10 根），三者各自獨立產生訊號 |
| 跌破（Sweep） | 最低價向下跌破最新的波段低點，且前一根還在它上方 |
| 收復（MSS） | 跌破之後，收盤由下往上穿越跌破當下最新的波段高點 → 訊號日收盤買進 |
| 失效 | 收盤跌破「跌破那天的最低價」，或跌破後超過 10 / 20 / 50 根（短 / 中 / 長）還沒收復 |
| 停損 | 跌破那天那根 K 棒的最低價 |
| 最小風險 | 進場價 − 停損價 ≥ 進場價的 10%，否則不進場 |
| 出場 | 漲到 1 倍風險（1R）後停損移到成本；2R 停利；最多持有 60 根，到期以收盤價出場 |
| 統計 | 只計已結束（停損、停利）的交易；保本出場也算勝 |

TradingView 指標與實盤掃描器的停損用的是 Order Block 低點；5 月的回測腳本寫成「跌破那天的最低價」，兩者不一致（見「稽核發現」第 11 項）。

## 研究背景

- **進場模型**：來自聰明錢（Smart Money Concepts）的交易概念。價格先被推到短線區間的邊緣、掃掉停損單，再反向突破。
  研究的第一個問題是：這個進場模型放到台股上是否有效。
- **為什麼接著研究籌碼**：短期股價最直接的推動力來自籌碼，三大法人、融資融券、外資持股比例是最容易取得的籌碼資料，所以先從簡易籌碼面著手。
  分點券商資料量太大（1.96 億筆），且當時抓取時被預先處理（÷1000），精確度不足，暫不納入。
- **期間**：研究在 2026 年 5 月進行，為期一個月，使用 2022-01～2026-05 的資料。
  6 月起上線測試；10 月整理成作品時重新稽核，並補進 2018～2021 年資料驗證。
- **工具**：資料來自 FinMind API，存於本機 MySQL，以 Python 分析（vibe coding 完成）。

## 演進

每個版本列出兩種設定下的結果，外資持股比門檻 15%。數字格式：**已結束 N / 勝率 / EV / MDD**。
兩欄的股票池、期間、規則都不同，**不能直接比較**；每一欄只說明「在這套設定下，這個版本的結果如何」。

| | 5 月 | 10 月 |
|---|---|---|
| 代表 | 5 月研究實際的做法（用 5 月腳本的規則重跑） | 第 2 部分的設定 |
| 股票池 | 687 檔（舊 `stocks` 表） | 上市櫃電子相關產業、含下市（975 檔有訊號） |
| 期間 | 2022-01～2026-05（開發期間） | 2018-01～2026-10 |
| 停牌日 0 元價格 | 保留（5 月當時的資料狀態） | 刪除，也刪除下市後的股價 |
| 停損 | 跌破那天那根 K 棒的最低價 | Order Block 低點（與實盤指標相同） |
| 同範圍持有中的新訊號 | 照常進場 | 不進場（與實盤指標相同） |
| 統計 | 只計已結束的交易；碰到 1R 後保本出場也算勝 | 計入持有期滿出場的交易；勝 = 損益 > 0 |
| 帳戶（算 MDD） | 起始 20 萬、每月 1 萬，每筆風險 = 帳戶 2%（5 月腳本的設計） | 起始 20 萬、每月 1 萬，每筆投入 5%、最多同時持有 20 檔 |

- 各版本自己的過濾條件與出場方式，兩欄都相同；最多持有 60 個交易日。
- 兩欄都是重跑的數字。5 月欄和當時紀錄的對照見本節最後的「對帳」。
- 10 月欄的勝率比 5 月欄低很多，是因為勝率的定義不同（保本出場不算勝），不是策略變差。
- 10 月欄看的是 2018～2026 的全期資料，不是樣本外，不能用來證明哪個版本有效；版本是否有效，見第 2 部分的研究結果。
- ⚠ = 原始腳本遺失，依當時的設計重建。
- 數字來源：`tools/version_history.py` → `results/VERSION_HISTORY.md`。

5 月欄保留了停牌日的 0 元價格：最低價 0 元會被當成跌破前低、停損也設在 0 元，產生大量假訊號。
沒有過濾條件的 v1，5 月欄的帳戶最大回撤達 −90.1%；加上越多過濾條件，假訊號越少，回撤也越小。

v4B 只記錄、不過濾，所以結果和 v4 相同。它的分析發現融資餘額增加的訊號期望值較高，接著用三組對照實驗拆解法人與融資的貢獻：

| 組別 | 條件 | 5 月 | 10 月 |
|---|---|---|---|
| v4C | 只有長週期 MSS | 2,902 / 46.8% / +0.013R / −86.7% | 8,205 / 36.0% / +0.214R / −39.4% |
| v4D | 長週期 + 融資 ≥ 0 | 1,391 / 52.0% / +0.138R / −68.4% | 4,303 / 35.6% / +0.216R / −36.6% |
| **v5** | 長週期 + 法人 20 日 + 融資 ≥ 0（20 日） | 818 / 57.1% / +0.260R / −39.5% | 2,562 / 35.6% / +0.220R / −35.0% |

- **5 月欄**：每加一個條件，EV 大致上升（v1 −0.043R → v5 +0.260R），這就是 5 月研究一路加條件的依據。但這個上升，有很大一部分是條件順帶擋掉了 0 元價格造成的假訊號。
- **10 月欄**：v1 到 v5 的 EV 都在 +0.195～+0.220R，**加條件幾乎沒有改變每筆的期望值**，只減少了訊號數。這和第 2 部分「籌碼條件沒有一個通過檢驗」的結論一致。

## 稽核發現（2026/10～11）

重新閱讀全部原始腳本與資料後發現的問題：

0. **停牌日的價格被存成 0，讓原始策略看起來是負期望值。** 資料庫有 4,866 列開高低收為 0（停牌或無成交）。
   舊腳本沒有排除：持倉期間只要碰到一天停牌，最低價 0 必定低於停損價，交易被記為 −1R；
   0 價也會製造假的 Sweep 與 MSS。用 5 月的規則重跑 v1（開發期間、舊統計方式）：
   保留 0 價列 → 已結束 5,154 / 勝率 44.0% / −0.043R（接近當時紀錄 5,558 / 45.8% / −0.016R）；
   移除 0 價列 → 4,107 / 57.1% / **+0.248R**（`results/VERSION_HISTORY.md`、`results/REPORT.md`）。
   「原始策略為負、加過濾才轉正」這個研究起點因此不成立：乾淨資料下，未過濾的 Sweep+MSS 每筆平均是賺的。
1. **v6～v6G 的外資持股比有前視偏誤。** `get_foreign_ratio_on_date(..., df['date'].iloc[-1])`
   取的是資料最後一天（2026）的外資持股比，套用到 2022 年起的全部訊號。
2. **v5B 半倉出場的 bug。** 切換價寫成 `ep + unit × TP1_MULT`（1R），但半倉獲利記為 +1.0R（應為 +0.5R）。
3. **v2A 週線 RSI 用到未來資料。** 查詢「訊號日 + 6 天以內」最近的週五，訊號在週一時會用到當週週五的收盤。
4. **統計方式。** 期望值只計停損、停利，持有期滿出場（TIMEOUT）被排除；v1～v5 的「TP1 保本出場（0R）」計為勝。
5. **成交假設。** 跳空跌破停損一律以停損價成交；未計手續費與證交稅。
6. **重複持倉。** 同一檔股票可在短、中範圍同時（甚至同日）進場，樣本不獨立。
7. **v6F、v6G 的 MDD、CAGR 不是帳戶績效。** 以「期初資金 × 2% × R」依出場月份加總，不受資金上限與持倉數限制。
8. **說明文字與程式不一致。** v6～v6E 的說明文字是複製來的實驗設計；
   v3 說籌碼套用所有範圍，實際只套用短、中範圍；v2A 說門檻 80，程式是 70。
9. **融資 ≥ 0% 會放行無融資資格的股票。** 融資餘額為 0 時變化率記為 0%，必定通過 ≥ 0% 條件。
10. **資料庫的融券賣出 / 融券回補部分對調。** 與 FinMind 重新比對 83 萬筆後，
    融券餘額 100% 正確；但 2022 年後有差異的列，全部都是 `short_sale` 與 `short_cover` 兩欄互換。
    回測過濾條件不使用這兩欄，不影響任何版本；v4B 的「融券回補比例」分析受影響。
    已用 `tools/refresh_short_columns.py` 依 TWSE 定義重新寫入（寫入前完整備份）。
11. **回測的停損和實盤指標不一致。** 所有 5 月回測腳本的停損都是「跌破那天那根 K 棒的最低價」，
    TradingView 指標與實盤掃描器用的是 Order Block 低點（跌破前 10 根到收復那根之間最低的 K 棒，和它的前一根取較低者）。
    5 月測到的不是實際交易的模型。第 1 部分保留原本的寫法，以呈現當時的做法；第 2 部分改用 Order Block。
12. **股票池漏掉約三成電子股與已下市公司。** 舊 `stocks` 表只用產業名稱含「電子」篩選（687 檔），
    漏掉約 289 檔上市櫃的半導體、光電、電腦週邊、通信網路等股票，也不含已下市的公司（存活者偏差）。
    另外，部分已下市股票在下市多年後仍零星出現有成交量的價格（FinMind 原始資料沒有）。
    第 1 部分沿用舊股票池；第 2 部分改用全市場資料表的 1,045 檔，並刪除下市後的股價。

## 重跑與驗證方法

`run_all.py` 用同一套程式重跑全部版本。先確認重跑程式和原始 v1 腳本跑同一份資料時，每一筆交易的進出場與損益完全相同（`tools/compare_legacy.py`；2026/10 比對時為 3,928 筆），再分兩種版本：

- **重現版（Replication）**：照原始腳本的邏輯與統計方式，用來和當時紀錄對帳。
- **修正版（Corrected）**：修正第 1、3、4 項；帳戶模擬再修正第 5、6、7 項。
  外資持股比改用訊號日前一天的值，週 RSI 只用已收盤的週 K，統計計入持有期滿出場的交易。

帳戶模擬：每月第一個交易日投入 1 萬元，策略與 0050 / 台積電定期定額的現金流完全相同，
以 XIRR（金額加權）與時間加權淨值的 CAGR / MDD / Sharpe 比較。部位大小跑兩種：每筆風險 = 帳戶 1%，以及每筆投入 = 帳戶 10%。

所有版本的條件都是在 2022-01～2026-05 決定的。資料庫原本只有這段期間，10 月從 FinMind 補齊 2018～2021 年的
股價、法人、融資融券與外資持股比（`tools/backfill_2021.py`，以 2022 年重疊資料校準單位），訊號表從 2018 年開始建立，再依訊號日切成以下期間：

| 期間 | 性質 | 說明 |
|---|---|---|
| 2018～2020 | **乾淨樣本外** | 從未參與任何決策；含 2018 Q4 貿易戰下跌、2020 年 3 月疫情崩跌 |
| 2021 | 半個樣本外 | 消融分析時看過 |
| 2022-01～2026-05 | 開發期間（樣本內） | 全部版本在這段期間開發 |
| 2026-06 之後 | 前瞻樣本外 | 上線後的資料；交易數還很少 |

訊號表原本從 2021 年 1 月開始建立，長週期趨勢與 20 日籌碼條件需要暖身，2021 年初的訊號被低估。
改從 2018 年建立後，開發期間的數字完全不變，但 2021 年的 v6 從 24 筆 / +0.515R 修正為 41 筆 / +0.357R。

### 每一版改了什麼、結論

| 版本 | 這一版的變動 | 5 月研究時的判斷 | 10 月重新驗證後 |
|---|---|---|---|
| **v1** | 起點：只有進場型態 | 期望值為負，需要加條件 | 判斷錯誤：負值是停牌日資料錯誤造成的，修正後每筆交易平均是賺的。但訊號太多，帳戶資金常卡在一起下跌的股票裡，三段期間都是最差的 |
| **v2** | **新增**長週期多頭才做短、中範圍訊號 | 有改善 → 保留 | 訊號減半，帳戶報酬和回撤都比 v1 好；v4 改用另一種判斷方式 |
| **v3** | **新增**近 20 日外資或投信累積買超 | 有改善 → 保留 | 開發期間和 v2 幾乎沒差，2018～2021 較差（總報酬 49.5% vs 64.7%）；v6 改成只看外資 |
| **v4** | **修改**長週期改用跌破收復判斷多空，且不再自己進場 | 有改善 → 保留 | 有改善，樣本外尤其明顯（2018～2021 總報酬 49.5% → 80.2%）。從 v6 拿掉它時，2018～2021 最大回撤從 −17.2% 擴大到 −21.6%，有防守作用 |
| **v5** | **新增**近 20 日融資餘額沒有減少 | 有改善 → 保留 | 第 1 部分中**最有效的一步**：總報酬開發期間 100.8% → 161.2%、2018～2021 80.2% → 154.0%（但第 2 部分的系統化檢驗沒有確認，見 README） |

- **主線 v2～v5 在開發期間幾乎沒有提高期望值**（+0.219 → +0.252R）。當時看到的改善主要來自停牌日 0 價與統計方式，不是過濾條件本身。
- **融資只有方向成立。** 從 v6 拿掉融資，2018～2020 從 +0.241 降到 +0.108R；但開發期間最好的「≥ +5%」（v6C）在 2018～2020 反而是 −0.198R。

- **長週期多頭是空頭年的防守條件。** 2018 年 v6 只出 11 筆（合計約 −9.5R），拿掉後 23 筆（約 −11.0R）；2018～2021 四年加總兩者都約 +34R。
- **族內微調一再在樣本外失效。** v6F、v6G、流動性門檻（v6H～v6J）在開發期間都比 v6 好，2018～2020 全部比 v6 差。

### 過度擬合檢驗（PBO）

把開發期間切成 8 段、輪流當訓練與測試（70 種切法），從 94 組版本 × 門檻中挑「訓練期最好的」，
看它在測試期排第幾：**PBO = 78.6%**，也就是挑出來的設定有近八成機率在新資料上排到後半段；
訓練期 Sharpe 越高，測試期反而越低（斜率 −0.94）。策略集合只含報告中的版本，實際試過的更多，所以這是下限。見 `results/pbo/PBO.md`。

## 第 1 部分的結論

1. **每筆交易賺錢，不代表帳戶賺錢。** v1 每筆平均小賺，但帳戶在 2018～2021 年總報酬只有 7.0%，最大回撤 −44%。
   訊號太多時，有限的資金常同時卡在一批一起下跌的股票裡。
2. **融資條件在第 1 部分看起來最有效**（v4 → v5 總報酬兩段都大幅提高），但只有「不減少」這個方向成立，而且第 2 部分的系統化檢驗沒有確認它。
3. **外資持股比只在開發期間有效。** 加上它的 v6 開發期間全面改善，2018～2021 年總報酬卻從 154.0% 掉到 27.6%。
4. **條件調得越細，越容易過度擬合。** v6 之後的微調在樣本外都比 v6 差，PBO 78.6%。
5. **研究方法本身有問題。** 一次改好幾件事、看完結果才決定保留哪個條件、沒有顯著性檢定，加上上述資料與程式錯誤，
   第 1 部分的結論都不夠可靠。這是第 2 部分重新做研究設計的原因。

> 樣本外的結果不拿來重新挑策略。v5 在 2018～2021 看起來比實盤版本好，但如果依據這四年改用 v5，這段資料就不再是「沒看過的」。

## 實盤掃描器與回測的差異（v6A）

| 項目 | 掃描器 | 回測 |
|---|---|---|
| 停損 | Order Block 低點 | 跌破那天那根 K 棒的最低價 |
| 同一根 K 同時碰停損與停利 | 算停利 | 算停損（保守） |
| 最長持有 | 無上限 | 60 根 |
| 同股同日短、中範圍皆有訊號 | 只取中範圍 | 兩筆都計 |
| 股價 | yfinance 還原價 | 資料庫未還原價 |
| 無融資資料 | 放行 | 擋掉 |

掃描器另有兩個待修問題：持股的外資持股比跌破 15% 後不會再收集該股價格，停損停利不會觸發；
每日訊號上限只計當日新訊號，未扣除既有持倉，也未檢查是否已持有同一檔。

## 限制

- **存活者偏差**：第 1 部分沿用舊股票池（2026 年的電子股名單、不含已下市），2018～2020 年的結果偏樂觀。第 2 部分已改用含下市的股票池。
- **樣本外筆數少**：v6 在 2018～2020 只有 80 筆，未達顯著。
- **停損與實盤不同**：第 1 部分的數字反映 5 月回測的停損寫法，不是實際交易的規則。
