# 資料說明

研究用到哪些資料、從哪裡來、股票池怎麼建立、資料怎麼清理。每張資料表的完整欄位與筆數見 [資料表欄位](DATA_SCHEMA.md)。

## 資料來源

所有資料都來自 [FinMind](https://finmindtrade.com/) API，存在本機 MySQL（資料庫 `tw_broker`）。資料庫裡有兩組資料表：

| 資料表 | 內容 | 誰在用 |
|---|---|---|
| `fm_` 開頭 | FinMind 全市場原始資料，欄位名稱、單位都照 FinMind 原樣保存，含已下市股票 | 第 2 部分 |
| `stocks`、`stock_prices`、`institutional_investors`、`margin_trading`、`foreign_shareholding` | 5 月研究時建立的電子股資料表（687 檔），寫入時已轉換欄位名稱與單位 | 第 1 部分（重現 5 月研究） |

研究使用的期間是 2018-01～2026-10。

### 第 2 部分用到的欄位

| 資料 | 資料表 | 使用的欄位 | 單位與處理 |
|---|---|---|---|
| 股票清單與產業 | `fm_stock_info` | `stock_id`、`stock_name`、`industry_category`、`type` | 用來建立股票池（見下一節） |
| 股價 | `fm_stock_price` | `open`、`max`（最高）、`min`（最低）、`close`、`Trading_Volume` | 未還原股價；成交量原始單位為股，換成張（÷ 1,000，保留小數） |
| 三大法人買賣超 | `fm_institutional` | `name`（只取 `Foreign_Investor` 外資、`Investment_Trust` 投信）、`buy`、`sell` | 淨買超 = 買 − 賣，原始單位為股，換成張（÷ 1,000，保留小數、不捨去） |
| 融資 | `fm_margin` | `MarginPurchaseTodayBalance`（融資餘額） | 只用變化率，不換單位 |
| 外資持股比 | `fm_shareholding` | `ForeignInvestmentSharesRatio` | 單位為 %；訊號只用訊號日前一個交易日的值 |
| 下市日 | `fm_delisting` | `date`、`stock_id` | 用來刪除下市後的股價 |
| 0050、台積電還原股價 | 不經過資料庫：`fetch_benchmarks.py` 直接向 FinMind（`TaiwanStockPriceAdj`）下載，失敗時改用 yfinance，存到 `data/benchmarks/` | 收盤價 | 定期定額的比較基準，股利再投入 |

讀取程式：`research/fm_data.py`。欄位名稱比對不分大小寫，找不到欄位時程式會列出實際欄位後停止。

## 股票池

研究對象是「上市、上櫃的電子相關產業股票，含期間內下市的公司」：

1. `fm_stock_info` 中**曾經**被歸在下列任一產業：半導體業、電腦及週邊設備業、光電業、通信網路業、電子零組件業、電子通路業、資訊服務業、其他電子業，以及舊類別名稱「電子工業」「其他電子類」。
2. 在上市（`twse`）或上櫃（`tpex`）交易，不含興櫃。
3. 一般股票：4 位數字代號、不是 00 開頭（排除 ETF 與特別股，例如 3036A）。
4. 含已下市的股票。

結果：**1,045 檔**，其中 997 檔有股價、48 檔曾下市。

### 和舊股票池的差異

5 月研究的舊股票池（`stocks` 表，687 檔）只用「產業名稱含電子」篩選，而且是當時還在交易的股票清單：

| | 檔數 | 說明 |
|---|---|---|
| 兩邊都有 | 675 | |
| 只在新股票池 | 370 | 舊股票池漏掉的半導體、光電、電腦週邊、通信網路等股票，以及已下市的公司 |
| 只在舊股票池 | 12 | 3 檔特別股（例如 3036A）；9 檔現在歸在「數位雲端類、電子商務業」等非電子產業 |

舊股票池漏掉已下市的公司，等於只回測「活到現在」的股票（存活者偏差），結果會偏樂觀。這是第 2 部分改用全市場資料表的原因（見 [研究設計](STUDY_DESIGN.md) 變更紀錄 2026-11-20）。

### 兩組資料表的內容是否一致

兩邊都有的股票，逐日比對（`tools/check_fm_source.py`）：

| 項目 | 一致比例 |
|---|---|
| 收盤價、成交量（張） | 100% |
| 融資餘額 | 100% |
| 外資持股比 | 100% |
| 法人買賣超（張） | 39.8%（方向一致 99.7%） |

法人買賣超不一致，是因為舊資料表把買進、賣出各自無條件捨去到張後才相減，`fm_` 資料表則是用股數相減後才換成張。
兩者只差在小數位數，方向幾乎完全相同；研究只用「累積買超是否 > 0」，影響很小。

## 資料清理

| 問題 | 處理 | 影響 |
|---|---|---|
| **停牌日的 0 元價格**：停牌或無成交的日子，開高低收被存成 0 | 刪除這些列 | 不刪除時，0 元會被當成跌破前低、停損也會被設在 0 元，產生大量假訊號，持倉中遇到停牌也會被誤判停損（研究歷程「稽核發現」第 0 項） |
| **下市後的股價**（只有舊資料表）：`stock_prices` 中 24 檔已下市股票，在下市多年後仍零星出現有成交量的價格（共 144 列）；`fm_stock_price` 沒有這些列 | 刪除每檔最後一個下市日（含）之後的股價。`fm_` 資料表本身沒有這個問題，這一步只是保險 | 舊資料表中，價格序列會跳過數年，產生 7 筆假訊號（`tools/check_delisted_prices.py`） |
| **融券欄位對調**（只有舊資料表）：`margin_trading` 2022 年後部分列的融券賣出、融券回補兩欄互換 | 依 TWSE 定義重新寫入，寫入前完整備份（`margin_trading_backup_20261026`） | 研究的過濾條件不使用這兩欄 |
| **資料不足**：回看期間不滿 k 天、沒有法人資料、融資基期為 0 | 該條件視為「不成立」 | — |

### 避免用到未來資料

- 法人、融資、外資持股比都只用**訊號日前一天以前**的資料；訊號在當天收盤才出現，當天的籌碼資料要等收盤後才公布。
- 週線、月線只用已經收完的週 K、月 K。
- 滾動前進測試中，訓練期間結束時還沒出場的交易，以訓練期間最後一天的收盤價計算市值，不使用之後的價格。

## 沒有使用的資料表

資料庫中另有財報（`balance_sheet`、`cash_flows`、`financial_statements`）、月營收（`month_revenue`）與分點券商資料（`broker_trades`，約 1.96 億筆；資料表欄位中的 1.86 億是資料庫的估計值）。
這次研究沒有使用：財報、月營收不屬於這次的籌碼研究範圍；分點資料量太大，也還沒有建立券商分點的分類。
